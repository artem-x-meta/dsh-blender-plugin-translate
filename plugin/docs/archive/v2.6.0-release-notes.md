# v2.6.0 release notes

> Released: 2026-10-21 · plugin **v2.6.0** · addon **v1.10 / protocol 11** · **15 model tools** ·
> plan catalog **33 family / 217 op** (**97 of them read-only**)
> Download: [GitHub Release v2.6.0](https://github.com/sixtysevenlf/dsh-blender-plugin/releases/tag/v2.6.0) ·
> Full record: [CHANGELOG.md](../CHANGELOG.md)

## In one sentence

The theme of this version is **GUI first, headless as fallback**: open the GUI by default; headless is only the fallback, but it is complete — without opening a Blender window you can still model, look at frames,
accept and deliver; the capability surface grows from **28 family / 186 op** to **33 / 217**, while the model tools remain **15** (all new capabilities go through
`blender_rt_plan`'s catalog, adding no tool names the model has to remember).

## Three upgrade steps

1. **Update the DSH plugin to v2.6.0 → restart DSH** (the plugin is a module loaded when DSH starts, and does not take effect without a restart).
2. **The Blender addon needs no change**: this version does not modify the addon, and an already installed v1.10 keeps working; the old `MCP for Blender` has not been supported since v2.3.
3. **Acceptance**:
   - `blender_rt_plan(op="catalog")` → **33 family / 217 op**, tool count **15**
   - With a GUI present, `curl -sS http://127.0.0.1:9877/doctor` → `kind=ok`
   - Pure headless: `blender_rt_worker(op="start")` + `op="see"` returning one frame proves itself (at that point doctor's bpy round-trip being unreachable is expected)

## Why it is worth upgrading

| Previous limitation | Now |
|---|---|
| Looking at one frame or running a piece of Python required an open Blender window | Resident headless session: after `worker start`, `see` takes about 50–100 ms per frame and `exec` is millisecond-level |
| A long render / long job lost its result on timeout | Job layer `rt_job` + ledger reconciliation: after a backend restart, `done/failed` is recovered from on-disk evidence instead of everything being judged `stale` |
| "Does it look like the reference image" could only be judged by eye | Reference image measuring tools `img_*` (size / contour / holes / symmetry) + same camera position QC `visualreport_report` (verdict-first) |
| Assembly interpenetration, floating blocks and gaps relied on feeling | `asm_scan` all-pairs classification (clash / contact / gap / float / contained / unresolved) + repair and export |
| No hard gate before delivery | `gate_*` + `deliver_export(require_gate=true)`: nothing is written to disk without passing the gate |

## New capabilities (by usage scenario)

### 1. GUI first; work gets done without opening a window too (fallback)

> By default open GUI Blender + Connect first; the headless capabilities below are the fallback path when there is no GUI / for batch work / for long jobs.

- `blender_rt_worker`: `start / exec / see / watch / reset / stop`, supports `preload`, `warmup`, idle TTL (default 15 min)
- `blender_rt_do` / `blender_rt_see`: passing `session` or `auto` falls back automatically to a headless worker
- `blender_rt_plan(..., session="auto")`: starts a persistent worker per family automatically and dispatches, without depending on the GUI
- `blender_rt_watch(session=...)`: headless per-frame sampling + hash, to tell "did it move / is it right"

### 2. Reconstruction from reference images

- `img_digest`: native-resolution measurement, contours, Hough, holes, symmetry, readability, output as a confirmable numeric table
- `img_probe` / `img_measure` / `img_calib`: probe, distance measurement, calibration
- `shapesolve_solve`: infer dimensions from two/three-view silhouettes (orthographic analytic projection + numpy rasterization, no rendering)

### 3. Assembly and delivery

- `asm_scan` → `asm_manifest` → `asm_merge` (automatic gate + snapshot before merge)
- `asm_repair(policy=safe|manual|aggressive)`: safe only does translate/snap and hard-forbids boolean operations; dry-run by default
- `asm_export`: GLB / FBX / OBJ + `manifest.json` + append-only `merge_ledger.jsonl`
- `gate_preflight` / `gate_checkpoint` / `gate_deliver` + `deliver_export(require_gate=true)`

### 4. Blockout and reference packs

- `blockout_base / batch / export`: declarative parts, mm / anchor, Workbench 3 views, GLB
- `blockout_refsheet`: 4 orthographic/perspective PNGs + 2×2 montage + `refsheet.json`
- `blockout_turntable`: Blender's built-in FFMPEG produces an MP4/H264 turntable

### 5. Acceptance and evaluation

- `visualreport_report`: same camera position QC, verdict-first, three-level fallback qc → imgtools → numpy
- `eval_run`: defect injection / baseline evaluation; cases with missing modules are marked `skipped` / `degraded` and are not falsely passed

## Stability and correctness

- **The ledger is based on files** (`runtime/recover.mjs`): after the backend restarts or is killed, do an on-disk reconciliation first (`summary.json` → artifacts → stdout final state);
  if it matches, return `done|failed` + `recovered:true` + evidence, so the model no longer has to `Get-Process` / `ls` to solve the case itself.
- **Multi-light hygiene**: recognizes `Shadow buffer full (N / M)` and emits a structured warning (`eevee_shadow_pool_full`) plus `K.light_hygiene`.
- **Progress channel**: `dsh_progress(**fields)` / `DSH_PROGRESS` are kept separate from stage, so long phases no longer "look stuck".
- **Two-dimensional write scope**: `blender_viewport op="lease" scope="collection:COL_Lights,prefix:LGT-"`, visible in both `/who` and 409 receipts;
  paired with `K.route_collections()` to route back by prefix.

## Fixes

- **issue #32**: on Windows `npm test` broke in the chain at `tests/linux_selftest.mjs`
  (the ESM dynamic import used a bare path `C:\…`, which was taken for a protocol name) → changed to `pathToFileURL(...).href`.
- **issue #33**: C5 in `tests/workdir_shared_selftest.mjs` was always red on Windows
  (it split a POSIX-style path with `path.sep`, which does not split at all on Windows) → changed to `path.posix.basename(...)`.
- **Documentation wording**: corrected the wrong statement that "the `/host/view/*`, `/host/pick*`, `/host/ready` routes are kept for compatibility" —
  those routes were deleted together with the panel in v2.3, and the only host routes that remain are `/host/selection`, `/host/scene-items`, `/host/jobs`.

## Documentation and skill

- README (Chinese and English), operations tutorial, configuration reference, install/deploy/migrate, AGENTS and CLAUDE are fully aligned with the v2.6 wording,
  and the stale statements 28/186, v2.5, v0.9.x and "GUI is mandatory" are removed.
- The bundled skill switches to an "architecture first" main line: catalog → plan op → worker session → receipt / verdict → gate / delivery;
  it adds a tool selection matrix, a standard state machine, P0–P2 recipes and anti-patterns, and demotes general Blender knowledge to an appendix.

## Compatibility

| Item | Description |
|---|---|
| Blender addon | **v1.10 / protocol 11**, unchanged in this version; the old `MCP for Blender` is not supported |
| Model tool count | Still **15**, and inputs/receipts stay backward compatible (fields are only added) |
| DSH-side panel | Deleted since v2.3; the selection entry point is Blender native selection → `N` panel "send selection to DSH" |
| GUI | Still fully supported; it is just **no longer a required item** |
| Upgrade | **Restart DSH** after updating the plugin; use `blender_viewport(op="restart")` only when the backend alone changed |

## Not covered / dependencies not installed

landmark / face (no cv2, MediaPipe), OCR, DXF, Open3D / manifold3d / glTF-Validator are **all not installed**;
creature and organic fine modeling, film-grade lighting / volumetrics / compositing, and character animation rigging are **not covered**. Do not use them as if they were "supported".
