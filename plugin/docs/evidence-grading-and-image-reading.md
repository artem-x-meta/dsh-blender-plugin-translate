# Evidence grading and image-reading discipline (v0.8.10 / external feedback 92 §4-§5 landed)

> Source: five-party measurement in the j20-build project (report 92). Core conclusion: **"100% of the lethal judgments came from scripts, not from looking at images"** --
> lead read ≈26 images (about 20-30k tokens), at least 2 of which were completely wasted duplicates; while the heavyweight defects that were caught
> (13 self-intersections, 39 zero-area faces, 90th-percentile dihedral angle 11.61°, UV uniqueness 21.5%, canopy seam 20.36 mm, per-part isolation failure)
> **were all measured by scripts**. So "looking at an image" is demoted from an **inspection means** to an **anomaly confirmation means**.

## 1. Cost model (do the accounting first)

Visual input cost ≈ proportional to pixel area (empirical formula \`tokens ≈ W×H/750\`):

| Purpose | Size | ≈tokens | Relative cost |
|---|---|---|---|
| Whole-aircraft beauty | 1600×900 | 1920 | **25×** |
| Whole-aircraft QC | 1280×720 | 1229 | 16× |
| Part QC | 960×540 | 691 | 9× |
| Binary contour overlay | 800×450 | 480 | 6× |
| **Anomaly small crop** | 240×240 | **77** | **1×** |

Corollary: **one whole-aircraft image = 25 small 240×240 crops**. And the image the model sees is a downsampled, re-encoded copy, while the script reads the original on disk --
**paying for a low-resolution copy vs getting the full-resolution original for free**: this asymmetry is the lever for optimization.

## 2. Four-level evidence system (only L2/L3 are allowed to read images)

| Level | Form | Who reads it | Cost per call | Use | When it must appear |
|---|---|---|---|---|---|
| **L0** | Numeric metric table (expected vs actual + PASS/FAIL) | Generated by script, the model reads **text** | ≈0 | Size/angle/self-check counts/elapsed time/IoU matrix/dihedral distribution/UV uniqueness | **Every round, every change** |
| **L1** | Binary contour overlay image (≤800×450, reference red / model blue / overlap black) | The model reads 1 image | ≈480 | Geometric deviation visible at a glance, and computable | Every stage gate |
| **L2** | Small crop of the anomaly region (≤320×320, ≤6 per call) | The model reads | ≈6×140 | Confirm "what the anomaly the script pointed out actually looks like" | **Only when L0 reports FAIL** |
| **L3** | Whole-aircraft finished render (beauty) | The model reads 1-2 images | ≈1900 | Final aesthetic verdict (ultimately decided by the user) | Milestones / delivery only |

**Core discipline: if L0 does not report FAIL, reading L1/L2 is not allowed; L3 is for the user only and is never the basis for geometric correctness.**

## 3. Per-round image-reading budget (hard-coded)

1. **≤ 6 images per round, each ≤ 800×450** (≈≤4.3k tokens/round).
2. **Before reading images**, the script must output "the N most anomalous regions" (ranked by: lowest IoU / highest 90th-percentile dihedral / largest boundary deviation / largest mask-area difference).
3. **Before reading an image, write the assertion first**: which 2-3 **testable propositions** this image is meant to verify.
4. **After reading an image, write the three-way split**: [confirmed observed] [inferred] [what I am not able to judge]; any visual judgment that cannot be confirmed with numbers
   must be labelled **"unconfirmed visual impression"** and must not be written as "passed".
5. Reserve only 1-2 whole-aircraft images for delivery confirmation.

> Counter-intuitive point: **a montage does not save tokens** (total pixels are unchanged); what it saves is **call count and attention**. To save tokens you can only "lower the pixels" or "not read the image".

## 4. Tool mapping (which op produces which level)

| Level | Produced by |
|---|---|
| **L0** | \`blender_rt_plan(op="audit_scene")\` scene mesh inspection · \`audit_mesh\` single-object deep-dive · \`audit_duplicates\` same-name resources · \`qc_compare\` (IoU/Dice/missing and excess area/boundary distance/profile difference, includes warnings) · \`qc_render_views\`'s \`render_views.jsonl\` (per image ms/bytes/md5/coverage/margin) |
| **L1** | \`qc_compare\`'s three-panel sheet (reference\|render\|overlay) · \`qc_render_views\`'s \`sheet=N\` (N-panel grid + grid + scale bar + per-panel metrics) |
| **L2** | \`montage\` (\`K.dsh_montage_api\`) crop montage: \`tile=420\`, total width ≤1700 px, 12-16 panels; when anomalously preferring, give only the 3 largest deviation regions |
| **L3** | \`qc_render_views\` multi-view renders (\`warmup=true\` keeps per-image timing clean) · \`blender_rt_see\` custom view |

**Threshold notes**: 12-16 panels / tile 400-420 / total width ≤1700 px come from j20-build measurements (ref-scout: 6 calls covered 66 images, saving about 51 single-image calls;
above ~1700 px the harness rescales again and the detail in small panels blurs first). These are **defaults, configurable**, not laws.

## 5. Scenario recipes

- **Every round of changes**: \`audit_scene\` + \`qc_render_views\` (3-4 views + jsonl) → read only the L0 table; only a FAIL goes to L2.
- **Stage gate**: add 1 L1 contour overlay (\`qc_compare\`'s sheet).
- **Delivery**: add 1 L3 beauty + \`audit_duplicates\` (to keep same-name forked resources out of the deliverable).
- **"Is this detail right?"**: first write it as a testable proposition (seam width in mm / number of peaks / dihedral percentile / UV uniqueness) → measure with a script → look at an image only when the script cannot say.

## 6. Two hard rules: pixel row order (E1) and batch rays (E2) (v0.9.3 / 93 feedback §6)

### 6.1 E1 · Blender's `image.pixels` / `foreach_get` are **bottom-up**

> **Hard rule: anywhere Blender's pixel buffer is compared against a PIL / cv2 / PNG decoder, apply `[::-1]` first.**

**Cost evidence**: because of this the reviewer misjudged "camera reconstruction and render do not match" and even suspected the render script had been modified, chasing it for **~4 rounds / 20 minutes**;
after adding `[::-1]`, the same comparison set: IoU **0.463 → 0.955**, **0.786 → 0.972**.

```python
import numpy as np, bpy

def load_rgba_top_down(path):
    """Blender image → (h, w, 4) float32, row order matching image coordinates (top→bottom)."""
    img = bpy.data.images.load(path, check_existing=False)
    w, h = int(img.size[0]), int(img.size[1])
    buf = np.empty(w * h * 4, dtype=np.float32)
    img.pixels.foreach_get(buf)        # foreach_get is 1-2 orders of magnitude faster than list(img.pixels)
    return buf.reshape(h, w, 4)[::-1]  # ← key: Blender's row 0 = the image **bottom**
```

**Comparison self-check (copy-paste, expected < 1/255)**:

```python
from PIL import Image
a = load_rgba_top_down("/mnt/d/work/out/front.png")
b = np.asarray(Image.open("/mnt/d/work/out/front.png").convert("RGBA"), dtype=np.float32) / 255.0
print("max_abs_diff =", float(np.abs(a - b).max()))   # without [::-1] you get a large "vertically flipped" difference
```

**Symptoms of not flipping**: the mask is upside down → IoU halves, profile difference explodes, and \`qc_compare\`'s "missing area" and "excess area" are **both** large at the same time
(the same contour cannot be both missing and in excess -- if you see that combination, suspect row order first).

**Pathways that already flip it for you** (do not flip twice):

| Pathway | Row order |
|---|---|
| `K.dsh_qc_api["load"](path)` → `(srgb[h,w,3], alpha[h,w])` | **already flipped to top→bottom** (qc.py docstring verbatim) |
| `K.dsh_qc_api["compare"]` / `qc_render_views`'s `ref_path` comparison | goes through the load above, already flipped |
| Your own `image.pixels.foreach_get` / `img.pixels[:]` | **not flipped** → you must apply `[::-1]` |

In one sentence: **use the qc API and you need not flip; do your own foreach_get and you must flip** -- mixing the two is where things crash.

### 6.2 E2 · For batch rays use `BVHTree.FromPolygons + bvh.ray_cast`, not `scene.ray_cast`

> **Hard rule: for per-pixel / per-sample-point batch ray queries, always build a BVH first and then call `bvh.ray_cast`;
> `scene.ray_cast` is only suitable for occasional "click a few points" queries.**

**Cost evidence**: the reviewer hit the 120 s / 600 s limit twice with `scene.ray_cast` (≈12 minutes + 2 rounds of rework);
after switching to `BVHTree` the same workload takes **0.6-0.9 s per camera position**. Reason: `scene.ray_cast` **goes through the depsgraph on every call**
(evaluate + update); per pixel means going through the depsgraph per pixel.

```python
import bpy, numpy as np
from mathutils.bvhtree import BVHTree

def world_tris(objs):
    """**World-space** triangles of visible meshes, (N,3,3) float64 -- same convention as audit.py's _bvh_from_tris."""
    dg = bpy.context.evaluated_depsgraph_get()
    out = []
    for ob in objs:
        if ob.type != "MESH" or ob.hide_render:
            continue
        me = ob.evaluated_get(dg).to_mesh()
        me.calc_loop_triangles()
        v = np.empty(len(me.vertices) * 3, dtype=np.float64)
        me.vertices.foreach_get("co", v)
        v = v.reshape(-1, 3)
        idx = np.empty(len(me.loop_triangles) * 3, dtype=np.int32)
        me.loop_triangles.foreach_get("vertices", idx)
        tris = v[idx.reshape(-1, 3)]                                    # (T,3,3)
        mw = np.array(ob.matrix_world)
        tris = np.concatenate([tris, np.ones((len(tris), 3, 1))], axis=2) @ mw.T
        out.append(tris[:, :, :3])
        ob.evaluated_get(dg).to_mesh_clear()
    return np.concatenate(out) if out else np.zeros((0, 3, 3))

def build_bvh(tris):
    V = tris.reshape(-1, 3).tolist()
    polys = [(3 * i, 3 * i + 1, 3 * i + 2) for i in range(len(tris))]
    return BVHTree.FromPolygons(V, polys, all_triangles=True)   # all_triangles=True → returned index = triangle index

bvh = build_bvh(world_tris([o for o in bpy.data.objects if o.type == "MESH"]))
hit = bvh.ray_cast((0.0, 0.0, 5.0), (0.0, 0.0, -1.0), 100.0)    # → (loc, normal, index, dist) or (None,)*4
```

**Batch usage (occlusion / visibility / parity test)**:

```python
def ray_hits(bvh, origins, dirs, limit=1e4):
    """origins / dirs: (M,3). Returns (M,) bool -- True on hit."""
    return np.array([bvh.ray_cast(tuple(map(float, o)), tuple(map(float, d)), limit)[0] is not None
                     for o, d in zip(origins, dirs)], dtype=bool)
```

Two practical cautions (measured conclusions from audit.py; copying them costs nothing):

1. **After a hit, advance eps along the direction before casting again** (otherwise you hit yourself in place and the parity count is entirely wrong); hard-code the iteration limit and **report unknown** --
   do not treat "could not decide" as "does not intersect";
2. The build cost of `BVHTree.FromPolygons` grows linearly with face count -- but the plugin **no longer degrades by face count by default** (it runs everything). Only when `DSH_*` env / `max_tris` is explicitly set to a non-zero value does it first bucket by bbox under that convention, or degrade to point-to-point distance.

> The `ds_raycast_batch()` kernel helper is **not implemented yet** (a suggestion from 93 feedback E2) -- until then, the two functions above are the usable form.

## 7. Measuring from images (appendix A / T-A4 landed, v0.9.3)

> Applicable scenario: **no orthographic three-view, only official 3/4 perspective beauty shots**, and sizes, station positions and proportions must be taken from them.
> Cost this round: the master image was uniformly downsampled to 1500 px (≈55 px/m) and then distributed -- a 0.1 m panel seam ≈5 px, a 0.05 m rivet ≈2 px,
> **which is effectively unreadable**; native resolution is about **126 px/m** (seam 12.6 px). The station table was filled in by the Lead **by eye** yet written down as a frozen contract,
> and 6 part branches aligned to it → **errors consistent with each other** (the assembly was perfect, the whole was off from the real ship); **zero quantitative validation** throughout (no silhouette IoU / edge overlay).

### 7.1 Four hard rules

| # | Rule | Why |
|---|---|---|
| 1 | **Never measure on a self-downsampled image**: measure on the **native-resolution** image; only downsample images meant for the model | after downsampling, a feature below 0.3 m is only a few pixels, so what you measure is noise |
| 2 | **Measurements must carry provenance and error**: record for every dimension the source image path + md5 / native size / downsample factor / px_per_m / conversion error | a number without provenance cannot be re-checked, and invalidation after a source image update cannot be judged |
| 3 | **Features below 0.3 m must have a native crop** (an unscaled crop of the original + coordinates) | this is the only criterion for "can it be read off the image at all" |
| 4 | **X-direction station positions from a perspective image must always be marked "approximate"** (with a ± error interval) and must not be written as a frozen contract | in a 3/4 perspective, displacement along the view direction cannot be converted directly; writing an eyeballed station position as a contract amplifies the error globally |

### 7.2 px/m calibration and provenance (copy and use)

```python
import json, hashlib
import numpy as np
from PIL import Image

def ref_measure_stub(image, p1, p2, known_len_m):
    """[temporary stand-in] Measure one known length on the native image → px_per_m, and record provenance.
    Note: the ref_measure primitive is not implemented yet (see §7.4); this is the minimal usable version."""
    im = Image.open(image); W, H = im.size
    md5 = hashlib.md5(open(image, "rb").read()).hexdigest()
    px = float(np.hypot(p2[0] - p1[0], p2[1] - p1[1]))
    return {"image": image, "md5": md5, "native_px": [W, H], "p1": p1, "p2": p2,
            "known_len_m": known_len_m, "px": round(px, 2),
            "px_per_m": round(px / known_len_m, 3),
            "err_m_per_px": round(known_len_m / px, 5),
            "err_m_at_300px": round(300.0 * known_len_m / px, 4)}   # accumulated error 300 px away from the calibration line

print(json.dumps(ref_measure_stub("/mnt/d/ref/aurora_native.png", (820, 640), (1620, 648), 6.45),
                 ensure_ascii=False))
# → {"px_per_m": 124.03, "err_m_per_px": 0.00806, "err_m_at_300px": 2.419, ...}
```

**A station table must look like this** (with error and source, otherwise it is not a contract):

```python
stations = [
  {"name": "nose",       "px_x": 412,  "metres": 9.50, "err_m": 0.24, "axis": "X",
   "confidence": "approximate", "src": "aurora_native.png", "md5": "…", "px_per_m": 124.03},
  {"name": "canopy_top", "px_x": 1010, "metres": 6.45, "err_m": 0.12, "axis": "Z",
   "confidence": "approximate", "src": "aurora_native.png", "md5": "…", "px_per_m": 124.03},
]
```

> Counter-example (really happened this round): a table like `{"nose": 9.5, "canopy_top": 6.45}` with **no error and no source** was handed down as a frozen contract --
> the 6 part branches aligned with each other beautifully, and the whole was off. **A station table without err_m and md5 is not allowed into the contract.**

### 7.3 Native crops (no scaling) and the readability criterion

```python
import os, json
from PIL import Image

def ref_crop_native(image, crops, outdir):
    """[temporary stand-in] Native-resolution crops (**no scaling**) + a metadata manifest.
    Note: the ref_crop_atlas primitive is not implemented yet (see §7.4)."""
    im = Image.open(image).convert("RGB"); W, H = im.size
    os.makedirs(outdir, exist_ok=True)
    rows = []
    for c in crops:
        x0, y0, x1, y1 = c["box_px"]
        tile = im.crop((x0, y0, x1, y1))          # key: no resize
        p = os.path.join(outdir, "%s.png" % c["name"])
        tile.save(p)
        rows.append({"name": c["name"], "box_px": [x0, y0, x1, y1], "px": [x1 - x0, y1 - y0],
                     "scale": 1.0, "source": image, "source_px": [W, H], "path": p})
    json.dump(rows, open(os.path.join(outdir, "atlas.json"), "w"), ensure_ascii=False, indent=2)
    return rows

def unreadable(features, px_per_m=55.0, min_px=8):
    """A feature smaller than min_px in the image = unreadable → use a closer source, or mark it "unknown" (no guessing)."""
    return [{"feature": f["name"], "m": f["m"], "px": round(f["m"] * px_per_m, 1), "verdict": "unreadable"}
            for f in features if f["m"] * px_per_m < min_px]

# Actual convention this round: distributed image ≈55 px/m
print(unreadable([{"name": "panel_seam", "m": 0.10}, {"name": "rivet", "m": 0.05}], px_per_m=55.0))
# → panel seam 5.5 px / rivet 2.8 px, all "unreadable"; on the native image (124 px/m) they become 12.4 px / 6.2 px
```

### 7.5 Silhouette comparison: can be done right now (T-A5)

`qc_compare` already has IoU / Dice / missing area / excess area / boundary distance / per-layer profile difference + a three-panel comparison image (reference | render | overlay),
**and it can be called directly headless**:

```python
blender_rt_headless(preload="qc", script="""
import json
r = K.dsh_qc_api["compare"]("/mnt/d/ref/aurora_front_native.png", [820, 300, 1500, 1400],
                             "/mnt/d/work/out/front.png", label="front",
                             out_dir="/mnt/d/work/out/qc")
print('HEADLESS ' + (r if isinstance(r, str) else json.dumps(r, ensure_ascii=False)))
""")
```

Convention (since v0.8.3; copy it, do not misremember): `iou` is **fixed alignment** (the honest value), and search alignment is given separately as `iou_search`;
**scale drift > 5%** and **search absorption > 0.05** both raise a warning; `ref_box` may be omitted (defaults to the whole image).

> **Stage-gate suggestion (appendix A.3)**: treat "blockout and proportions locked" as a **hard checkpoint** --
> entry condition = **a station table with errors + an atlas of native feature crops + silhouette IoU meeting the target**; if not met, do not dispatch part tasks.
> This round skipped it and went straight to detail reconstruction, so all the engineering effort of "chamfer every panel, count faces on every rivet" went into the wrong contour.
